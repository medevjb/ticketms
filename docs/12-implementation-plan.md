## Task completion contract

Use the service pattern throughout all phases (PRD D13, architecture ADR06). P02 establishes only the needed `app/Services/` conventions; P03 implements TicketService/SlaService, P04 AssignmentService, P05 ConversationService/AttachmentService, P06 NotificationDeliveryService, and P07 import/bulk orchestration services. Admin services are introduced with their modules. Controllers/jobs remain adapters; no parallel Actions layer. Each phase verifies the same service behavior through its real entry points, including authorization, transaction rollback and record-level idempotency. Bulk results are transient response data; do not add run/item persistence without owner approval.

Each task names FR/BR/T IDs, files/schema affected, permissions and transaction boundary, input/failure cases, minimal test command/results and remaining risks. Update traceability if scope changes. Do not mark phase complete on code presence alone. Verify package versions and applicable skills/rules for each change. No generic infrastructure abstraction until a concrete task needs it.
